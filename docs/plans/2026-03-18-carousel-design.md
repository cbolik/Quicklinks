# Carousel Navigation — Design Spec

**Date:** 2026-03-18
**Project:** Spotify Playlists static page

---

## Problem

The app currently shows a single list of playlists. The user wants to add additional lists (albums, podcasts/shows, audiobooks, etc.) as separate pages that can be swiped between on mobile and navigated with arrows/dots on desktop.

---

## Goals

1. Support 4–6 pages of Spotify links, each with its own label and content.
2. Native-feeling horizontal swipe on iPhone and iPad.
3. Dot indicators at the bottom showing the current page.
4. Left/right arrow buttons on desktop (in addition to dots).
5. Each page vertically centers its content.
6. Adding a new page = adding another `<section>` block in the HTML.

---

## Design

### Approach: CSS `scroll-snap`

A horizontal scroll container with `scroll-snap-type: x mandatory`. Each page is a full-viewport-width section that snaps into place. The browser handles all touch physics (momentum, snapping, overscroll) natively on iOS — the same feel as swiping between home screens.

### HTML structure

The existing `<main>` element becomes a scroll-snap container (class `carousel`). Each page is a `<section class="page">` containing its own `<h1 class="label">` and `<nav>` with links. After the carousel, a `<div class="indicators">` holds the dot indicators and arrow buttons.

```html
<main class="carousel">
  <section class="page">
    <h1 class="label">Playlists</h1>
    <nav>
      <a href="spotify:playlist:...">...</a>
      ...
    </nav>
  </section>

  <section class="page">
    <h1 class="label">Albums</h1>
    <nav>
      <a href="spotify:album:...">...</a>
      ...
    </nav>
  </section>

  <section class="page">
    <h1 class="label">Shows</h1>
    <nav>
      <a href="spotify:show:...">...</a>
      ...
    </nav>
  </section>
</main>

<div class="indicators">
  <button class="arrow arrow-left" aria-label="Previous page">‹</button>
  <div class="dots"></div>
  <button class="arrow arrow-right" aria-label="Next page">›</button>
</div>
```

### CSS

- `.carousel`: `display: flex; overflow-x: auto; scroll-snap-type: x mandatory; -webkit-overflow-scrolling: touch;` with hidden scrollbar.
- `.page`: `flex: 0 0 100%; width: 100%; scroll-snap-align: center;` — each page occupies full viewport width. Content is vertically centered with flexbox (same as current layout).
- `.indicators`: Fixed at the bottom of the viewport. Contains dots and arrow buttons.
- `.dots`: One dot per page, generated by JS. Active dot is `#1DB954` (Spotify green), inactive dots are `rgba(255,255,255,0.25)`.
- `.arrow`: Shown only on non-touch devices via `@media (hover: hover)`. Dim white, subtle, positioned left/right within the indicators bar.

### JavaScript additions to `script.js`

The existing IIFE gains carousel logic:

1. **Dot generation**: Count `.page` elements, create one dot per page inside `.dots`.
2. **Scroll listener**: On `scroll` event (debounced via `scrollend` or `IntersectionObserver`), determine which page is visible and update the active dot.
3. **Dot clicks**: Clicking a dot scrolls to the corresponding page via `scrollTo({ behavior: 'smooth' })`.
4. **Arrow clicks**: Left/right arrows scroll by one page width.
5. **Keyboard**: Left/right arrow keys navigate between pages on desktop.

### Pages for initial implementation

1. **Playlists** — existing 7 links (keep as-is)
2. **Albums** — 4 dummy `spotify:album:` links
3. **Shows** — 3 dummy `spotify:show:` links

## Non-Goals

- No pages are expected to require vertical scrolling at current content sizes, but if content overflows, native vertical scrolling within the page must still work.
- No animated page transitions beyond native scroll-snap behavior.
- No persistence of which page was last viewed.
- No dynamic page creation — pages are static HTML sections.
